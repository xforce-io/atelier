# Atelier

使用简体中文。先确定用户正在操作的工作区；不把当前代码仓库自动当作 Atelier 工作区。

执行 `atelier --workspace <工作区> --json skill describe --protocol 2`。已有明确团队或任务时加 `--team <ID>` 或 `--task <ID>`，两者互斥。读取返回的身份、范围、指导与操作索引，再按用户意图调用实际入口。缺少 CLI、describe 失败或 JSON 主版本不为 2 时停止相关调用，报告具体原因；不要猜旧版命令。`workspace_missing` 才进入初始化，损坏工作区不能当作空工作区重建。

describe 代表当前本机本人，不能选择数字员工身份或自行声明角色。该结果是操作指导，实际授权和状态仍由每次核心调用核验。切换团队/任务，或权限、版本冲突后重新 describe 并查询事实。

`pendingDecisions` 若非空，先把每条的问题、选项和当前产出写进对话，再回答其他内容。不等用户来问进展。用户没有明确接受或拒绝时，不调用 `task accept` 或 `task reject`。

写操作使用稳定的 `--request-id`；未收到回复时先 `request show <ID>`，同内容沿用原 ID 重试。普通 CLI 返回排队不代表成员已处理。工作由独立服务与成员收件箱推进；宿主提交后可以退出，不代数字员工承接、安排、修改候选或制造检验结论。

用户的授权只覆盖其请求范围。普通聊天、没有回复、预先同意开发或“继续”不能作为对当前交付的正式验收。展示实际待办、产出版本、证据及限制后，只把用户对该次请求的明确接受/拒绝传给核心，保存脱敏 decision-ref；任务版本变化后旧决定不能沿用。凭据只通过受保护的本地输入设置，不索要聊天中的秘密。
