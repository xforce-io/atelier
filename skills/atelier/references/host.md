# 本机本人入口

按 describe 的范围和当前操作索引调用 CLI，具体参数使用该命令的 --help。`pendingDecisions` 若非空，先把每条的问题、选项和当前产出写进对话，再回答其他内容。不等用户来问进展。用户没有明确接受或拒绝时，不调用 task accept 或 task reject。管理身份可以维护工作区和获准团队，但不等于数字员工团队负责人；数字负责人自己的消息由独立运行服务唤起该成员处理。

空工作区先初始化，再建立连接、数字员工、团队和显式授权。保存对象不等于连接可用；按所选接入检查环境。显式 runtime start 后才允许后台处理；runtime status、task show、mailbox list 查询事实不启动工作。用户提交目标后，无需宿主不断轮询或串联各阶段。

回应待办时读取事项 kind、处理者、依据版本和可选动作。补充答复与实际落实分开，恢复选择不授权或解除未知。正式接受/拒绝须对应用户当前明确决定；保存 request ID、请求/任务版本、产出及检验引用和脱敏 decision-ref。缺少决定保持待办，过期则重新展示当前事实，不自动把旧“同意”用于新版。

导出使用指定 Artifact 到新目录或空目录，保留 partial 限制。导出不等于验收、合入或部署。遇到 unknown 先核对真实资源；不能修改数据库或假造停止结果以推进任务。

登记本机环境前先问齐名称和代码目录。有服务时再问端口和健康检查路径。缺的字段不要猜测。若服务不是直接从代码目录运行，例如镜像、编译产物或已安装的包，建议一条核对命令，用户确认后再登记。用户要求自动执行时，先说明这等于把本人身份交给命令，命令可以调用 Atelier CLI；说明之后停下来，等用户再次确认，才调用 environment update。`pendingDecisions` 里 `host_command` 事项要原样展示问题、选项和影响，用户明确同意后才回应「执行」。

CLI 连接检查须明确 `--worker`，在对应 `connection prepare` 和交互 `connection login` 后执行 `connection test`。查看 `connection show` 的 `workerReadiness`，不能把一个 Worker 的检查成功当成其他成员就绪。检查无业务 Task/Run；它会请求一次受控的原生模型诊断。旧请求仅重放或核对，修复后用新 requestId 重测。诊断中断时先按原请求或 `runtime reconcile` 核对所属资源，不导入宿主登录绕过专用环境。
