# Issue #20 验证路径

标准为 [L1 v0.1 第 8 节](../../../../docs/design/20-leader-continues-after-stop/product.md#8-验收与效果验证)。本文件只提供路径。

## S1.A1 新事实交给负责人

数字员工团队里，执行或返工停止且资源已核对，并留下新事实。查询负责人收件箱，应有 1 条对应工作消息。`task decision list` 上该任务的恢复事项不因此增加。任务结果不是已接受。

同一事实在服务再次启动后不产生第二条消息。

## S2.A1 空停止不再自动排队

投递已是 blocked 或 uncertain。负责人这一轮没有新事实，停止原因不变。处理结束后该投递状态不变，Run 数量不增加。

## S3.A1 普通停住没有新的恢复事项

只发生普通停住时，`task decision list` 不出现新的 retry、wait、cancel。授权撤销、凭据缺失或连接失败仍会出现一条恢复事项，不能把这条算进「新增 0」。

## S4.A1 已受理代码执行不能原样重试

对已停止的 execute 或 rework 投递执行一次 `mailbox retry`。结果是拒绝，该投递状态与重试前相同。

## S5.A1 第三次返工

任务已有 2 次返工，且仍有新的失败依据。再安排一次返工应成功。把返工上限显式收紧到 1 之后，第 2 次仍应被拒绝。

## 真实入口

S1 与 S3 用真实 CLI 查询收件箱和 `task decision list`。S4 用真实 CLI 的 `mailbox retry`。S2 与 S5 由核心测试证明计数和安排结果；没有单独的新命令。

不在本路径部署，不指定业务仓库里的缺陷或补丁。
