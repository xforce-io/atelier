# 本机环境部署

Issue #22。L1 `docs/design/22-host-environment-deploy/product.md` v0.5。L2 同目录 `technical.md` v0.5。

范围：S1.A1–S4.A5。核心测试见 L2 第 10 节。S1.A3 是宿主里的真实登记对话，本文件的开发阶段不把它记为通过。

## S1.A1

本人用 CLI 登记、查看和更新本机环境。运行服务不必因此重启。

## S1.A2

不安全的代码目录、端口、重叠和服务字段被拒绝。

## S1.A3

宿主按 `skills/atelier/references/host.md` 问齐登记字段，说明自动执行，并原样展示 `host_command` 待决定。此路径留待验证环节在真实宿主中执行。

## S1.A4

部署成员没有登记环境的工具。工具只有 `host_exec` 和 `deploy_verify`。

## S2.A1–A2

接受时导出只读产出和改动清单，并冻结当时的环境登记。未点名目标，或登记已变化，部署记录阻塞，任务不关闭。

## S2.A3

没有部署职责的团队仍在接受后关闭。沿用既有验收测试。

## S2.A4

未知环境名，以及写了部署目标却没有代码输入，都不能写入契约。

## S3.A1–A5

部署成员提交本机命令。逐条确认先进入 `pendingDecisions`，拒绝则不执行。自动确认直接执行。非法参数、超时和运行服务中断都留下记录，不自动重跑。

## S4.A1–A5

`deploy_verify` 按冻结方式核对。文件比对加健康检查通过后，任务关闭且结果为已部署，验收记录仍为接受。失败保持开放。非部署成员、活动 Run、进行中的命令和登记变化都不能把任务关掉。不能再自报部署结果。
