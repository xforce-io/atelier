# S7 验证路径

状态：部分核心边界已实现，真实团队未执行。标准为 [L1 v0.10 第 8 节](../../../../docs/design/1-first-team-delivery/product.md#8-验收与效果验证) 的 S7.A1–A5；本文件只提供路径，不复制另一套验收标准。

## 真实入口

数字团队不依赖宿主阶段调用，从提交目标持续处理工作消息到人类待办；含普通说明与消息循环。

贯穿任务使用 [L1.8.1 井字棋小游戏](../../../../docs/design/1-first-team-delivery/product.md#81-贯穿验收场景井字棋小游戏)，按其中的正常交付、缺陷返工与故障恢复路径分别取证，并关联 S1/S6/S2/S3/S4/S5 对应功能地图；游戏要求不在本文件重复维护。

## 驾驶与证据

本人非团队负责人时直接安排必须拒绝，即使持有 task.arrange；本人担任团队负责人时另验证获准路径。

关闭宿主并以另一 CLI 查询，记录成员决定/回复因果、人类等待及不可用成员跳过、总预算；脚本代成员决定不能算通过。

对 S7.A1 逐次关联执行、交接和返工安排与真实成员操作，确认运行服务只处理已有投递。无交接决定时不自动送检、无返工决定时不自动重做的分支，按 L2.8 另做 Integration，不能用该注入代替真实成员全链路。

已有核心测试区分普通成员消息与核心业务/故障通知，并验证成员工具绑定、操作去重及权限门禁；这些测试没有真实模型，不覆盖 S7 完整路径。

对 S7.A2 核对同一 Worker 收件箱中的不同类别、成员直接选择的普通消息与业务操作产生的通知；记录 recipient、kind、任务和因果引用。普通正文不能被自动升级为授权、执行安排或验收事实。

导出后实际打开同一产出版本的游戏并保留操作证据，不能只检查成员自报或测试摘要。缺陷若在首次交接前修复，如实记录通过，失败返工仍未覆盖；不得修改固定产出或伪造检验失败。样例基线、可信检查及离线浏览器环境缺失时记录 BLOCKED，不填充虚构的运行记录。

CLI 和产品 Atelier Skill 分别验证；需要真实成员的路径不可用 stub 或宿主脚本替代。版本、对象和原始脱敏证据对应 L1/L2 v0.10。API 运行服务已有实际入口及合成凭据的启停/崩溃恢复测试；真实模型协作、两种 agent CLI 与产品 Skill 尚未贯通，完整验收仍 BLOCKED，不填 pass。

运行服务的 CLI 通道已有真实管理 CLI/SQLite/Docker/milkie 集成：验证绑定投递的核心工具、同 Task 续接、不同 Task 会话隔离和停止回收。登录与 Pi 响应均为合成替身；没有团队自主安排、真实模型或 Skill 宿主验收结论。
