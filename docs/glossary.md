# 名词表

| 规范名 | 一句话定义 | 禁止别称 |
|---|---|---|
| Atelier/工坊 | 面向人和数字员工持续团队协作的产品，中文名为工坊。 | — |
| Human–Agent Organization/硅基—碳基组织 | 本设计对人和数字员工共同参与、围绕目标建立职责与授权关系的组织的称呼，不预设双方具有相同能力或责任后果。 | — |
| Agent/智能体 | 能够根据目标、上下文和反馈在运行时选择行动的系统，不自动具有 Atelier 中的持续成员身份。 | — |
| RSI/递归自我改进 | 递归自我改进（Recursive Self-Improvement），指系统将改进持久传递给后续版本，并使产生、评估或选择后续改进的机制本身成为改进对象的过程。 | — |
| Organizational Learning/组织学习 | 团队将工作反馈转化为经验证并用于后续工作的能力或协作方式变化的过程，不仅是保存历史记录。 | — |
| GPUI/桌面界面框架 | Atelier 第一方桌面界面采用的 Rust UI 框架，负责呈现与交互，不拥有独立于核心的工作事实。 | — |
| milkie/暂无中文名 | 提供 agent runtime 能力的独立底层库，不承担 Atelier 的数字员工或团队产品抽象。 | — |
| agent runtime/智能体运行时 | 执行 agent 定义并管理其推理、工具调用和运行过程的基础机制。 | — |
| coding agent/编程智能体 | 提供代码任务推理与工具执行能力的具体执行器。 | — |
| Executor/执行器 | 接收执行请求、推进工作并返回执行事件及结果的机制，可基于 milkie 或 coding agent。 | 数字员工 |
| Execution Configuration/执行配置 | 描述数字员工使用哪些执行器及相关能力参数的配置。 | — |
| Capability Declaration/能力声明 | 执行器对其支持的启动、输入、中断、恢复及可落实的 Guardrail 等能力的显式说明。 | — |
| Execution Event/执行事件 | 单次执行过程中由执行器报告、经核心校验后关联到 Task 与 Worker 的事件。 | — |
| Run/单次执行 | 某个执行器从启动到结束或中断的一次运行活动。 | 任务、会话 |
| Run Termination/执行结束 | 单次执行停止运行的事实，不代表检验通过或任务验收。 | 完成、交付 |
| First-Class Entity/一等公民 | 具有独立身份、生命周期或持久记录，可被引用、操作和检查的核心对象。 | — |
| Worker/工作成员 | 具有持续身份、可通信和承担工作职责的协作主体，中文称工作成员，包含 Human Worker 与 Agent Worker。 | — |
| Human Worker/人类成员 | 由人响应通知、操作并提交工作结果的 Worker。 | — |
| Agent Worker/数字员工 | 通过执行器推进工作并提交结果的 Worker，具有独立于执行器和单次执行的持续身份，产品中称数字员工。 | agent、执行器、机器人 |
| Authorized Actor/有权主体 | 在当前范围内对某项操作持有显式授权的 Worker；授权不由 Worker 类型或团队负责人身份自动产生。 | — |
| Decision Request/待决定事项 | 工作推进需要特定有权主体补充输入、授权或作出取舍的事项，包含补充、取舍、验收，以及凭据缺失、授权撤销或连接失败时的负责人恢复。已核对的普通停住交给团队负责人，不因此新增恢复事项。须关联当前依据、可选动作、影响及决定落实结果。 | — |
| Task/任务 | 具有目标、约束和结束条件的通用持续工作对象，可交给一个 Worker 或一个 Team，不以 Git 仓库为前置，生命周期独立于当前对话的聚焦状态。 | — |
| Subtask/子任务 | 由父任务委派、结果汇合回父任务的 Task；父任务保留最终交付责任。 | — |
| Task Contract/任务契约 | 对 Task 的目标、Law、检验方式、Guardrail、输入及交付要求的版本化表达。 | — |
| Goal/目标 | 工作需要达成的可观察结果，应与产出及执行活动区分。 | — |
| Verification Method/检验方式 | 根据任务契约通过测试、工具、独立检查或人工判断收集证据并判断要求的方式。 | — |
| Verification Profile/检验配置 | 固定可执行检查、运行环境与输出要求的配置，供核心采集指定版本产出的独立检验证据，模型不能自行修改。 | — |
| Inputs and Preconditions/输入与前置条件 | 开始或继续任务所需的资料、权限和依赖条件。 | — |
| Delivery and Handoff Requirements/交付与交接要求 | 任务契约中对预期产出、接收者所需信息及后续职责的要求。 | — |
| Contract Version/契约版本 | 标识任务当前或历史要求的版本，用于关联执行、检验与验收依据。 | — |
| Law/结果性质 | 任务要求结果或相关系统必须满足的性质，可用自然语言或形式化方式表达。 | — |
| Guardrail/执行约束 | 限定执行行为、资源使用和停止条件的约束，中文称执行约束。 | — |
| Stop Condition/停止条件 | Guardrail 中规定执行或自动返工必须暂停并交由明确主体处理的边界，触及该边界不等于任务已结束。 | — |
| Work Intake/承接 | Worker 或 Team 明确接受一项工作并落实任务负责人的决定，Team 由团队负责人作出，直接承接的 Worker 自任任务负责人；收到消息不等于承接。 | — |
| Delegation/委派 | 有权主体将一项工作或子任务明确交给 Worker 或 Team 承担的操作。 | — |
| Verification Record/检验记录 | 针对指定任务契约和产出版本保存检验主体、方式、证据及结论的记录。 | — |
| Acceptance Record/验收记录 | 保存有权主体接受或拒绝指定交付的决定、对应版本、检验依据及决定原因的记录。 | — |
| Deploy Duty/部署职责 | 团队上显式指定的可选职责，由该成员接收部署投递并提交部署结果。不由成员显示名推断。 | 运维 |
| Deploy Record/部署记录 | 与验收记录分开保存的部署状态、对应验收和原因。 | 验收、完成 |
| Host Environment/本机环境 | 本人在工作区登记的本机部署目标，包括代码目录、可选服务端口与健康检查，以及命令确认方式；不承载权限。与执行配置中的 CLI 环境无关。 | CLI 环境、工作区 |
| Host Command/本机命令 | 部署成员在部署目标上提交、由运行服务以本机用户身份执行的一条命令，按环境设定逐条经本人确认或自动执行。 | 宿主 Shell |
| Deploy Verification/部署核对 | 核心按环境登记的方式（文件比对，或本人登记的核对命令）并结合可选健康检查，判断生产是否对应已验收产出的一次核对；通过才记为已部署。 | 部署结果自报 |
| Task Responsibility/任务职责关系 | Worker 在某个 Task 中承担任务负责人、执行者、检验者、验收者或部署者职责的关系。 | — |
| Handoff Relation/交接关系 | 关联发送者、接收者、产出版本、后续职责及接收状态的协作关系。 | — |
| Self-test/自测 | 执行者对本 Run 的指定候选版本运行受控检查并记录结果，不形成独立检验记录或验收决定。 | 独立检验、验收 |
| Verification/检验 | 根据任务契约收集证据并判断要求是否满足的活动，不等于最终验收。 | 验收、审批 |
| Verification Pass/检验通过 | 检验记录对指定契约与产出版本给出满足要求的结论，不代表任务已验收。 | 完成、验收 |
| Acceptance/验收 | 由有权主体根据当前任务契约与检验结果接受交付的决定。 | 检验、完成 |
| Rework/返工 | 首次执行受理后，执行者因检验失败、验收拒绝、阻塞或已核对运行错误，在已有工作基础上以新 Run 继续并形成新产出的工作。 | — |
| Artifact/产出 | 执行或协作产生、可被引用及交接的工作结果；代码产出须对应可固定、可追溯的内容。 | — |
| Candidate/候选 | 当前执行 Run 可修改的文件视图，提交后仍须核对资源停止并固定为可追溯产出。 | 产出 |
| Delivery/交付 | 提交给有权主体验收、由一个或多个指定版本产出构成的整体结果。 | — |
| Evidence/证据 | 支持检查或检验判断的可追溯材料，应关联对应的契约及候选或产出版本，并标明由系统采集或由 Worker 自报。 | — |
| Handoff/交接 | 将明确的产出、上下文和后续职责交给下一 Worker 的协作活动。 | 转发 |
| Team/团队 | 持续存在、具有且仅具有一名团队负责人、组织 Worker 并承担交付责任的团队。 | — |
| Team Leader/团队负责人 | Team 中唯一承担工作承接、任务负责人指定、跨任务协调和升级事项处理职责的成员，由一个 Worker 担任。 | 负责人（单独使用）、管理员 |
| Task Owner/任务负责人 | 在已承接 Task 中唯一承担组织分工、协调依赖和汇合交付职责的 Worker，直接承接者自任，也可由团队负责人指定或兼任。 | 负责人（单独使用） |
| Team Membership/团队成员关系 | Worker 与 Team 之间包含角色、权限和参与规则的关系。 | — |
| Conversation/会话 | 承载 Worker 之间消息交流的持续对象，可关联多个 Task，每次明确交互同一时刻最多聚焦一个 Task，聚焦变化不改变任务生命周期或他人的交互上下文。 | session |
| channel/频道 | Team 内按主题组织持续交流与可见范围的会话入口。 | — |
| direct/直接会话入口 | 特定 Worker 之间直接交流的会话入口。 | — |
| Business Feedback Loop/业务闭环 | 将执行效果反馈转化为检验、问题定位和后续任务的持续过程。 | — |
| Workspace/工作区 | 当前本机使用者管理成员、团队、任务及其持久工作记录的独立本地范围。 | — |
| Model Connection/模型连接 | 遵循 milkie 统一连接契约，保存模型 API 或 agent CLI 的接入配置，不代表 Worker 身份或任务授权。 | — |
| Execution Context/执行上下文 | 由 milkie 管理、可跨 Run 续接的执行状态，Atelier 保存其与 Worker、Task 和执行配置版本的关联。 | — |
| Session Continuation/会话续接 | 使用既有执行上下文开始新一轮交互，不等于自动恢复中断执行、代码快照或外部副作用。 | — |
| Atelier Skill/工坊操作技能 | 供宿主及数字员工按实际授权获取协作指导与操作说明的产品入口，内容由运行入口适配，不持有独立工作事实或绕过核心规则。 | 团队执行器、自主团队负责人 |
| Blocker Record/阻塞记录 | 保存任务执行中无法继续的原因、相关版本、处理者及修复依据的记录，报告成功不代表执行已停止或问题已解决。 | — |
| Work Message/工作消息 | 在任务范围内持久记录发送者、接收者、工作意图、内容引用和因果关联，并可触发成员处理的消息；投递不等于承接或完成。 | — |
| Mailbox/收件箱 | 按接收 Worker 汇集不同类别工作消息及其投递与处理状态的持久集合，由该成员处理，独立于成员是否正在运行及任何聊天窗口。 | — |
| Delivery Receipt/投递记录 | 保存一条工作消息向指定成员投递、领取、处理或终止的状态及关联 Run，用于追踪和去重。 | — |
| Workspace Runtime/工作区运行服务 | 在本机按持久投递为接收成员提供运行机会并管理停止、执行核对与资源约束的服务，不选择业务下一阶段，业务决定由有权成员作出。 | — |
| 出站代理 | 在隔离网络边界按可信策略转发指定外部目标连接的组件，不提供核心管理操作或扩大成员权限。 | — |
