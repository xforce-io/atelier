# 名词表

| 规范名 | 一句话定义 | 禁止别称 |
|---|---|---|
| Atelier | 面向人和数字员工持续团队协作的产品，中文名为工坊。 | — |
| milkie | 提供 agent runtime 能力的独立底层库，不承担 Atelier 的数字员工或团队产品抽象。 | — |
| agent runtime | 执行 agent 定义并管理其推理、工具调用和运行过程的基础机制。 | — |
| coding agent | 提供代码任务推理与工具执行能力的具体执行器。 | — |
| 执行器 | 根据执行配置推进工作并返回执行事件及结果的机制，可基于 milkie 或 coding agent。 | — |
| 执行配置 | 描述数字员工使用哪些执行器及相关能力参数的配置。 | — |
| 单次执行 | 某个执行器从启动到结束或中断的一次运行活动。 | — |
| 参与者 | 能在协作中通信或承担职责的人或数字员工。 | — |
| 数字员工 | 具有持续身份、职责、工作记录和执行配置的协作主体，不等于 runtime 定义或单次执行。 | — |
| Task | 具有目标、约束、检验方式和生命周期的一份工作，中文称任务。 | — |
| 任务契约 | 对 Task 的目标、Law、检验方式、Guardrail、输入及交付要求的版本化表达。 | — |
| Law | 任务要求结果或相关系统必须满足的性质，可用自然语言或形式化方式表达。 | — |
| Guardrail | 限定执行行为、资源使用和停止条件的约束，中文称执行约束。 | — |
| 检验 | 根据任务契约收集证据并判断要求是否满足的活动，不等于最终验收。 | — |
| 验收 | 由有权主体根据当前任务契约与检验结果接受交付的决定。 | — |
| 产出 | 执行或协作产生、可被引用及交接的工作结果。 | — |
| 证据 | 支持检验判断的可追溯材料，应关联对应的契约和产出版本。 | — |
| 交接 | 将明确的产出、上下文和后续职责交给下一参与者的协作活动。 | — |
| Team | 持续存在、组织参与者并承担交付责任的团队。 | — |
| 团队成员关系 | 参与者与 Team 之间包含角色、权限和参与规则的关系。 | — |
| 会话 | 承载参与者之间消息交流的持续对象，不等于 Task 或单次执行。 | — |
| channel | Team 内按主题组织持续交流与可见范围的会话入口。 | — |
| direct | 特定参与者之间直接交流的会话入口。 | — |
| 业务闭环 | 将执行效果反馈转化为检验、问题定位和后续任务的持续过程。 | — |
