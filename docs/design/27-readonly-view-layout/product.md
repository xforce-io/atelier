# L1 产品设计：只读界面点开成员后仍能看到工作区

版本：v0.1，2026-10-09；状态：Draft。关联 [Issue #27](https://github.com/xforce-io/atelier/issues/27)、[Issue #25](https://github.com/xforce-io/atelier/issues/25)、[名词表](../../glossary.md)、[L2 v0.1](technical.md)。

确认来源：2026-10-09 本次会话。用户看过 Playwright 点出的四项后，要求记成 Issue 并端到端修复、再复测。该确认适用于本版。本稿不自批为 Approved。

本版只补 #25 只读界面上已经露出的四项。点谁看谁、消息内容、空发送者显示「核心」、接收者认消息自己的接收者、打开时较新消息在消息列表可视范围内，都保持不变。

1. 点开有消息的工作成员后，窗口顶部的工作区标识和运行状态仍留在窗口内。较新的消息在消息列表自己的可视范围内，不靠把整页顶走来实现。
2. 窗口宽度为 390px 时，工作成员和工作消息上下排列。消息列表宽度大于 200px。页面内容宽度不超过窗口。
3. 这名工作成员没有发出或收到的工作消息时，显示「这名工作成员没有发出或收到的工作消息。」
4. 不存在的工作成员显示「找不到这名工作成员」。不存在的路径显示「没有这个地址」。两页都有回到只读界面首页的链接。

范围外：发送、编辑、成员管理、启停工作区运行服务；运行状态继续使用与 `runtime status` 相同的 state 原词；不改消息正文。
